## 학습
- **여러 에이전트가 같은 파일을 편집하는 병렬 계획은 그대로 실행하면 서로를 덮는다.** 계획이 "S1~S4 병렬 가능"이라고 적혀 있어도, 산출 대상이 단일 파일이면 **scout-parallel / assemble-serial**로 형태를 바꿔야 한다 — 에이전트는 텍스트만 반환하고 파일 삽입은 메인 세션이 단독 수행. 병렬성은 "읽고 초안 쓰는" 비싼 부분에서만 얻으면 충분하다.
- **에이전트 산출 텍스트는 후처리가 필요하다고 가정할 것** — 마크다운 escape(`&gt;`), 임의 구분자 삽입 같은 오염이 흔하다. 어셈블리 스크립트에 unescape·strip 단계를 처음부터 넣고, 삽입 후 `grep`으로 잔존 0을 확인.
- 문서화 작업의 사후 보증은 "경로 정확성"까지다(doc-sync 테스트가 `live − spec == ∅`로 보증). **응답 JSON 키의 세부 정확성은 핸들러 기반 best-effort**로 남고 스키마 drift는 여전히 수동 DoD — 이 한계를 완료 시점에 명시해야 나중에 과신하지 않는다.
