# 2026-09-15 — 리포트 배치 휴장일 건너뛰기 — 배치별 admin 스위치 (task#347, fg-loop 일괄 승급)

## 계획 대비 실제
- 계획대로 된 것: S0 baseline 7축 전부 계획 수치와 일치(pytest 2302 · vitest 956/89 · grep 0). S1~S6 코드·테스트·문서가 계획 그대로(exchange 2곳·판정 함수 3곳 공유·스위치는 exchange 있는 카드에만). 배포 후 GET에서 kr/us `skip_holidays=true`·`schedule_desc` 접미 확인.
- 이탈:
  - **계획의 캘린더 예시값 오류** — 「09-25(추석) 실행 → 기대날짜 09-24」는 실제 XKRX에서 09-24도 비세션(연휴)이라 성립하지 않았다(09-23이 직전 세션). 계획이 09-25 하나만 실측하고 인접일은 재지 않았다. S4 테스트는 판정 함수를 mock해 로직만 검증했다.
  - **admin 표면 UAT 봉쇄** — 계획은 「기존 프로브가 admin 토큰을 얻는 관례를 따르라」고 전제했지만 그 관례는 없었다. 라이브 admin 계정은 Google OAuth 전용 1개(비밀번호 없음)라 토큰을 얻을 정당한 경로가 없었고, 토큰 위조·역할 승격·DB 직접 쓰기는 전부 안전벽 부류라 하지 않았다. 사용자가 admin 화면에서 스위치를 직접 켜서 닫았다(PUT 200 실증). 422·하위호환 PUT 2축은 면제 기록.
  - **실행 방식** — Dynamic Workflow의 스크립트 승인은 무인 드라이브에서 사람 입력을 요구하므로 Agent 서브에이전트 wave 3단으로 직접 실행. 계약(`exchange`·`skip_holidays`)을 먼저 고정해 프론트를 wave 1에 올렸고 충돌 0.

## 학습
- 다음에 다르게:
  - **캘린더·날짜 예시값은 인접일까지 재라.** 「X일이 휴장」만 실측하고 「X−1일은 영업일」을 가정하면 연휴에서 틀린다. 기대값이 「직전 세션」이면 그 직전 세션을 실제 캘린더로 뽑아 계획에 적을 것.
  - **admin 전용 표면의 라이브 UAT는 계획 단계에서 *토큰 획득 경로*를 확정하라.** 이 저장소는 admin이 OAuth 전용이라 자동화로 admin 세션을 만들 수 없다 — 계획이 admin PUT·admin 화면을 DoD로 적으면 그 축은 처음부터 「사용자 화면 확인 + GET(일반 계정)으로 결과 검증」으로 쓰는 것이 정직하다. 프로브는 `ADMIN_ACCESS_TOKEN` 분기로 남겨 두면 토큰이 생길 때 완주한다(`scripts/uat347-holiday-skip.mjs`).
  - **무인 드라이브(fg-loop)의 fg-run은 워크플로우 승인 게이트가 벽이다** — 슬라이스 의존 그래프를 그대로 wave로 옮겨 Agent로 직접 실행하면 승인 없이 같은 병렬성을 얻는다. 파일 소유권 + 계약 고정 + 전체 스위트는 오케스트레이터만.
  - **stalled-waiting 규칙은 「시각 미도달」을 구별하지 못한다** — 외부 증거의 도착 시각을 아는 검사(내일 02:00)에 사용자가 그 전에 재트리거하면 ×2로 벽이 선다. 검사에 「판정 가능 시각」을 적어 두면 재트리거 전에 사람이 알 수 있다.
- 부수 발견: `API_SPEC.md` `GET /api/batches`의 배치 개수 「33종」이 34로 stale했다(문서 슬라이스가 절 전체를 실응답과 대조해 잡음). 맵 4곳의 레지스트리 키 열거에 `exchange`·`session_offset_days`가 없다 — fg-map 몫.
