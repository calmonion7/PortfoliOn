# 2026-10-01 — cxa: 등록 프로젝트 PLAN·RUN 세션을 새 iTerm 창 탭으로 일괄 생성 (#362)

## 계획 대비 실제
- 계획대로 된 것:
  - `~/.cc-projects` + `~/cc-all.sh` + `alias cxa`
  - 새 iTerm 창 탭 일괄 생성
  - 겹침 시 세션마다 y/N
  - N이면 bg는 attach 탭, 터미널은 건너뜀
  - `--dry-run`
  - 오류 경로(없는 프로젝트, agents 실패, 이름이 안 풀림)
- 차이:
  - **y의 의미가 바뀌었다.** 그릴링에서 「종료(대화 보존) = `claude stop`」으로 정했지만 1차 UAT에서 실패했다. stop된 bg 세션은 `--all` 목록에 남고, 사용자가 목록에서 열자 데몬이 `claimed-spare`로 재기동했다. 그래서 `[PortfoliOn] PLAN`이 2개가 되어 「종료 안 됨」으로 인지됐다. 사용자가 rm을 택했고, `claude rm`이 실행 중 세션에도 즉시 동작하며 transcript를 남기는 것을 재현으로 확인한 뒤 재실행했다.
  - S0 전제 재현은 「stop이 이름을 푸는가」만 쟀다. 그 성질은 참이었지만 사용자 목표(목록에서 사라짐)와는 다른 축이었다.
  - 검증 하니스 함정 2건(스크립트 결함 아님):
    - ① 스텁 `claude`의 `for row in $(jq …)`가 이름의 공백에서 JSON을 잘라 겹침 0으로 보였다.
    - ② `script` pty에 입력을 즉시 넣으면 첫 응답이 버려져 y가 N으로 처리됐다(입력 에코 없음이 단서).

    둘 다 판정 전에 원인을 실측으로 가려 오진을 피했다.

## 배운 점
- 다음엔 다르게:
  - **외부 도구의 상태 의미가 걸린 선택지는 메커니즘 성질(「대화 보존」·「항목 삭제」)이 아니라 사용자가 보게 될 결과로 설명하고 물을 것.** 예: 「y 후 세션 목록에 이 세션이 남는가 / 열면 되살아나는가」. stop의 「재개 가능」은 곧 「목록에 남고 열면 재기동」이었다.
  - **전제 재현(S0)은 목표의 관측 축으로 잴 것.** 「이름이 풀리는가」뿐 아니라 「y 후 `claude agents --all`에 무엇이 남는가」까지 한 번에 봤으면 1차 UAT 전에 차이가 드러났다.
  - 스텁으로 JSON 배열을 순회할 때는 `while IFS= read -r row; done < <(jq -c '.[]')`를 쓸 것(`for … in $(jq …)`는 공백에서 깨진다). pty 하니스(`script -q /dev/null`)에는 프롬프트가 뜬 뒤에 입력하도록 sleep 간격을 둘 것.
  - UAT가 「이 대화 자체를 지우는」 동작이면 결과를 그 대화에서 받을 수 없다. 확인 경로(다른 세션에서 fg-run 재개, 또는 대체 증거)를 미리 정해 둘 것.
- 후속 후보: 터미널 세션에서 ←(에이전트 뷰)로 가면 새 세션 ID의 bg 잡으로 이어 붙여지며(`continued-in`) 이름이 소실된다.
  - 648c4470 `[PortfoliOn] RUN` → 584d279e AI 제목 "clear-conversation-state"
  - cc10c64a `[lab-taebro] RUN` → 69a54bf4 이름 없음
  - c963768c → e8db505a는 유지. 원인 미확정.
  - bg 프로세스는 데몬이 띄워 cc.sh env를 받지 못하므로 #361 hook으로는 덮이지 않는다.
