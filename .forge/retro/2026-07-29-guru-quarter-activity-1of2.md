### Divergences

- **D1 (의도적)** 워크플로우 대신 직접 실행(6연속). 다만 이번은 프론트-only가 아니라 **백엔드 수집**이었다 — "소형이면 직접 실행"이 프론트 한정 규칙이 아님을 확인한 첫 사례.
- **D2 ⚠️ 라이브 전수 프로브가 계획에 없던 실데이터 버그를 잡았다 — 활동 페이지의 최신 분기가 보유 스냅샷보다 오래될 수 있다.** `aq`에서 보유 `Q2 2026` / 활동 최신 `Q4 2025`. 원인은 **활동 페이지가 변동이 있던 분기만 나열**하는 것. 그대로 조인하면 **3분기 전 매도가 「이번 분기 전량매도」로** 뜬다. A 정본 가드 덕에 `port_pct`는 이미 안 붙었지만 `sold_out`은 A를 안 거치는 독립 산출이라 새어나왔다. → 분기 정합 가드(둘 다 확인·일치할 때만 보강) + 회귀 2건. **계획이 못 본 축**: A·B의 *종목* 정합만 완료기준에 뒀고 *분기* 정합은 없었다 — 두 페이지가 같은 신고분을 본다고 **암묵 가정**했다.
- **D3 ⚠️ 프로브의 첫 단언이 리터럴이어서 정상 데이터를 FAIL로 찍었다.** `period-xcheck`를 "보유 분기 == 활동 분기"로 썼는데 라이브가 반증하는 리터럴이다. 참인 불변식은 "**불일치하면 보강을 생략한다**". 회고 #228의 "판정은 리터럴이 아니라 불변식으로"를 **CLAUDE.md 가토에 있는데도 프로브 작성 시점에 또 어겼다.**
- **D4 (계획 초과)** 프로브에 `pagination-exercised` 축 추가 — 절단 매니저가 **0명**이라 계획의 절단 단언이 한 번도 실행되지 않았다(`L` 추적 경로가 미검증인 채 통과 가능). "활동행 100을 넘긴 매니저가 존재한다"(VAN 121행)로 못박음. **0건 통과를 성공으로 읽지 말라**(task#232 계열)의 프로브판.
- **D5 (관찰·미수정)** 활동 이력이 한 분기뿐인 매니저는 `L=2..5`를 헛요청하고 `truncated`가 잘못 붙는다. "행<100이면 완결" 가드로 없앨 수 있으나 dataroma가 페이지 크기를 바꾸면 **조용한 절단**으로 뒤집힌다 — 현재는 시끄럽게 실패하고 해당 매니저 0명이라 미수정.
- **D6 (관찰·미수정, 기존 위험)** `_run_crawl`은 전 매니저가 실패해도 `managers: []`를 저장해 **기존 데이터를 지운다**. task#48/#50의 "빈 결과 캐시 박제 금지" 계열 위반이 구루 크롤에 남아 있다.
- **D8 ⚠️ 계획의 페이지 상한 근거가 틀렸고 실측이 정정했다 — 상한 5는 여유가 0이었다.** 계획은 "78명은 1요청, 5명만 +1~2"라 적고 `_ACT_MAX_PAGES=5`를 뒀는데, 근거가 **fg-ask 프로브가 `L=1`만 받아 100행에서 잘린 값**이었다. 전수 실측 최대는 `FE`의 **430행 = 정확히 5페이지**로 상한에 딱 걸려 통과한 것. 상한을 10으로.
- **D9 (인프라 churn, 자기해소)** `git log -1`이 이전 커밋을 찍어 커밋 소실로 보였으나 reflog상 `commit → (폴러가 낡은 origin/main으로) reset → (재fetch 후) reset` 순서였고 최종 `HEAD == origin/main == 5ec872c`로 **손실 0**. task#238 D6과 **2연속 동일 아티팩트**.

## Learnings

- **Do differently next time**:
  - ⭐ **두 소스를 조인할 땐 *레코드* 정합뿐 아니라 *시점(분기)* 정합도 완료기준에 넣을 것**(D2). 두 페이지가 같은 신고분을 본다는 건 가정이지 보장이 아니다. 불일치 시 보강을 통째 생략(wrong < missing)이 안전하다.
  - ⭐ **잘린 관측값을 모집단의 최대로 읽으면 상한이 항상 과소 설정된다**(D8). fg-ask 프로브가 페이지 1장만 받았는데 그 값으로 `MAX_PAGES`를 정했다 — 회고 #225 계열(**추정 금지, 실측하라**)의 *페이지네이션판*. 상한 상수는 **전수 실측 최대의 2배**로.
  - ⭐ **`git log -1`로 폴러 churn을 판정하지 말 것**(D9, #238 D6과 2연속) — `git rev-parse HEAD` vs `origin/main` + `gh run list`로.
  - **"단언이 한 번도 실행되지 않았다"를 프로브가 스스로 말하게 할 것**(D4) — 조건부 단언(절단·에러 경로)은 표본이 0이면 조용히 통과한다. "그 경로를 실제로 밟은 표본이 존재한다"를 별도 축으로 못박을 것.
  - **CLAUDE.md에 있는 교훈도 프로브 작성 시점엔 또 어긴다**(D3) — 프로브를 쓸 때 "이 단언은 리터럴인가 불변식인가"를 한 번 자문할 것.
- **후속 후보(미해결)**: ⚠️ **`_run_crawl`이 전 매니저 실패 시 `managers: []`로 기존 데이터를 지운다**(D6) — task#48/#50 계열 위반, 데이터 손실 위험. ② D5의 헛요청·오탐 `truncated`.
