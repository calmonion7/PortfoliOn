## 학습
- **behavior-preserving 이동은 "손으로 옮기지 말고" 원본 라인 슬라이스 + `git show HEAD:<file>`과 byte-diff로 증명할 것.** 본문 1바이트 불변을 기계적으로 보장하면 리뷰·테스트가 볼 표면이 확 줄어든다(적대적 리뷰 서브에이전트를 이 감사로 대체할 수 있었다).
- **re-export로 공개 표면을 보존할 때의 진짜 위험은 monkeypatch 경로다.** 테스트가 `svc.<심볼>`로 패치하는 대상이 *이동분*에 있으면 split 후 namespace가 갈려 조용히 안 먹는다. 이동 전에 "테스트가 패치하는 심볼 전수 추출 → 이동/잔류 분류"를 먼저 하고, "클러스터 내부 함수를 패치하고 다른 클러스터 함수가 그걸 보길 기대하는 테스트"가 없는지 확인할 것.
- 실행 시 남긴 열린 질문: "god-module 분리 시 re-export로 공개 표면 보존" 규약을 ADR로 기록할지. **판단: ADR 미승급** — 되돌리기 쉽고(합치기만 하면 됨) 트레이드오프가 자명해 3조건 미달. 위 monkeypatch 감사 절차가 실질 교훈이므로 retro에 보존.
