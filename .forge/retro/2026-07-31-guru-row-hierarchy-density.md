# 2026-07-31 — 구루 카드 행 위계·헤더 밀도 개선 (루프 밖 ad-hoc · 커밋 2371c02b)

> forge 활성 슬롯이 빈 상태에서 사용자 스크린샷 1장으로 시작한 ad-hoc 작업이라 `plan.md`·`run.md`가 없다.

## 계획 vs 실제

- **요청대로 된 것**:
  - 스크린샷 화면(구루 → 투자금 탭)의 시각 위계·밀도 개선. before/after를 같은 프로브로 실측해 대조.
  - 카드 높이 102.5 → **80.1px**(투자금) · **71.1px**(인기순·가중치), 문서 높이 194k → **156k**.
  - 순위·티커·값이 서로 다른 축(실측 t=499.3 / 486.8 / 473.5)에 있던 것을 한 baseline으로.
  - narrow350 필 행 84px(2줄) → **40px**(1줄), 첫 카드 395 → **306px**.
  - vitest 240 green(27파일) · 라이브 프로브 111단언 ALL PASS(커버리지 1773, 재실행 간 총계 동일) · 스위트 후 `git status` 부수효과 0.
  - 판정축을 처음부터 분리해 짰다 — 잘림은 `scrollWidth`(#241), 접힘은 `Range.getClientRects()`(#247), 넘침은 카드 content box 실측(#228), 막대는 리터럴이 아니라 불변식(1위=트랙 꽉 참·단조 비증가·≥2px).

- **이탈**:
  1. **문제의 무게중심이 실측으로 뒤집혔다.** 스크린샷만 보고 "펼친 설명란이 화면 절반을 먹는 것"을 최대 문제로 봤는데, 실측하니 ① 첫 카드까지의 458px 중 **~270px은 이 화면과 무관한 PWA 설치 배너**였고(narrow350엔 배너가 없어 395px) ② 진짜 비용은 **1723행 × 22px = 38,000px**로 헤더 절감분(48px)의 **800배**였다. 결과도 그렇게 갈렸다 — 첫 카드 −10%인데 문서 높이 −20%.
  2. **프로브 111단언 ALL PASS 상태에서 육안이 2건을 잡았다.** PC 칩이 캡션과 1,000px 넘게 떨어져 그룹으로 안 읽힘 / 값과 액션이 같은 시선 높이 12px로 붙어 한 덩어리로 읽힘. **둘 다 넘침 0·잘림 0·접힘 0을 정상 통과**했다 → CLAUDE.md ⑩으로 승급.
  3. **범위가 1탭 → 3탭으로 넓어졌다.** `.guru-stat-row`·`WatchlistBtn`이 투자금·인기순·가중치 공유라, 투자금만 고치면 앱 안에 카드 레이아웃이 두 종류 생긴다.
  4. **봉인된 uat247 프로브의 리터럴 단언을 갱신했다** — 필 라벨을 `포트폴리오 규모 상위` → `규모 상위`로 축약하면서 `groupLabel === '포트폴리오 규모 상위'`가 거짓 FAIL이 됐다. 이유 주석과 함께 갱신.
  5. **미검증 축 1건 — 하단 탭바 겹침.** baseline 프로브가 `nav` 셀렉터로 `masthead-nav`(h=0)를 잡아 "겹침 483px"이라는 헛값을 냈다(#238 ⓒ를 그대로 재현). 무의미하다고 판단한 것까지는 맞았으나 **축을 고치는 대신 최종 프로브에서 빼버렸다** — `.m-page { padding-bottom: 100px }`가 새 카드 높이에서 충분한지는 재지 않았다(카드가 *줄어서* 회귀 위험은 없다).

## 배운 것

- **다음에 다르게 할 것**:
  1. **요소 *간* 거리는 별도 판정축이다.** 이탈 2번. 넘침·잘림·접힘은 전부 "단일 요소가 자기 상자 안에 있는가"를 묻고, "A와 B가 한 그룹으로 읽히는가 / 분리돼 읽히는가"에는 원리적으로 블라인드하다. 원인은 대개 `margin-left:auto`·`space-between` 같은 **"남는 공간" 의존 정렬**로, 같은 규칙이 310px과 1400px에서 정반대로 동작한다. **CLAUDE.md ⑩ 승급.**
  2. **before 실측은 검증이 아니라 문제 *우선순위* 재정렬 도구다.** 이탈 1번. 스크린샷에서 읽은 "가장 큰 문제"는 그 프레임에 보이는 것에 편향되고, **반복 요소(리스트 행)의 비용은 프레임 밖에 누적돼 눈에 안 띈다**. 한 행 22px은 사소해 보이지만 1723행이면 헤더 전체의 800배다. 착수 전 실측은 "고칠 것이 맞는지"뿐 아니라 **"무엇부터 고칠지"**를 바꾼다. (승급 후보로 올렸으나 사용자 판단으로 회고 로그에 유지 — CLAUDE.md 해당 항목이 이미 ①~⑩로 길다.)
  3. **"surgical"은 파일 수가 아니라 *결함 단위*로 판정한다.** 이탈 3번. 같은 결함이 공유 CSS/컴포넌트를 통해 N개 표면에 나타나면 N개를 고치는 게 surgical이고, 1개만 고치면 **레이아웃 불일치라는 새 결함**을 만든다. CLAUDE.md의 "#230·231·232 선제 전수 grep 금지 — 감사 대상 파일 수는 작업량이 아니다"와 방향이 반대처럼 보이지만 같은 원리다(둘 다 *파일 수로 범위를 정하지 말라*): 전자는 "실제로 깨지는 것만", 이건 "실제로 같은 결함인 것만". 선례는 task#103(`StockActions` 통합).
  4. **봉인 프로브의 리터럴 단언은 불변이 아니다.** 이탈 4번. UI가 정당하게 바뀌면 갱신 대상이고(#225 "정당한 변경에 거짓 실패하지 않아야"), 갱신할 때 **왜 바뀌었는지 주석을 남겨야** 다음 사람이 "누가 단언을 약화시켰나"로 읽지 않는다.
  5. **프로브 결함을 발견하면 축을 버리지 말고 고쳐서 남길 것.** 이탈 5번. 셀렉터가 틀렸다는 걸 인지하고도 "baseline 스크립트니까"로 넘겼더니, 최종 프로브에서 **그 축이 통째로 사라졌다**. 헛값을 내는 축과 없는 축은 다르다 — 전자는 고치면 되고 후자는 다음 사람이 존재 자체를 모른다.
  6. **트레이드오프는 되돌릴 수 있게 명시하고 넘길 것.** 캡션의 `— 비율은 이 총액 대비` 제거는 정보 삭제라 내 판단 영역이 아닐 수 있어, 근거(같은 설명이 패널에 있고 그 토글이 이제 캡션 바로 옆)와 함께 사용자에게 넘겼다.
