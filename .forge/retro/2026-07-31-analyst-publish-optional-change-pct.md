# 2026-07-31 — 발행 API가 명시적 `change_pct: null`을 거부해 발행 전체가 422로 막히던 것 해소 (task#250, 버그리포트 H1)

## 계획 대비 실제

- **계획대로 된 것**
  - S1(TDD): `PointMetric.change_pct`를 `Optional[float] = Field(None, allow_inf_nan=False)`로. red-first가 예측 그대로 발화(`assert 422 == 201`) → 수정 후 통과. NaN 핀 테스트는 이빨 검증(`allow_inf_nan=False` 일시 제거 → `assert 201 == 422` 실패 → 원복)으로 실효성 확인. 전체 스위트 1460 passed.
  - S2: 배포 후 무쓰기 라이브 스모크 — `ZZNOSNAP` + `change_pct: null` → **409**(수정 전이면 422), `analyst_reports` 쓰기 0.
  - 문서 무변경(`API_SPEC.md:2124`·`CLAUDE_COWORK_API.md:601`이 이미 `change_pct?`로 정확), blast radius 1건, 신규 ADR/용어 없음 — **그릴링이 미리 실측해 둔 4건이 모두 그대로 맞았다.**
- **이탈**
  1. **워크플로우 대신 직접 실행.** 한 줄 타입 변경 + 테스트 2건 규모라 다수 서브에이전트는 과잉(eco 모드 + fg-run "규모가 작으면 직접 처리").
  2. **S2에 사용자 `!` 실행이 불필요했다.** 계획은 "프로덕션 호출이라 필요할 수 있다"고 봤으나, `docker exec -i`로 컨테이너가 **자기 env의 `COWORK_API_KEY`** 를 읽어 스스로 호출하니 시크릿 노출 0으로 성립.
  3. **배포 직후 API가 ~5분 무응답이었고, 그 원인에 대한 내 첫 설명이 틀렸다.** 아래 참조.

## 학습

- **다음에 다르게 할 것 ①: 인과 설명을 회고에 쓰기 전에 타임스탬프로 재라.** 첫 스모크가 `Connection refused`로 헛돌자 나는 run.md에 "uvicorn은 lifespan startup을 끝낸 뒤에야 포트를 바인딩하고, 기동 경로의 리포트 배치가 그 시간을 먹는다"고 적었다. **실측하니 틀렸다** — 컨테이너 시작 `22:00:24` → 스케줄러 배선 완료 `22:00:25`로 **lifespan은 0.6초**였고(`main.py:241` lifespan = `_migrate()` + `sched.start()` + 데몬 스레드, 배치는 스케줄러 스레드라 비블로킹), 포트는 기동 배치의 **마지막 로그 `22:05:41` 직후**에 열렸다(분당 로그 49·19·22·20·20 → **4** → 2). 즉 블로커는 lifespan이 아니라 **기동과 동시에 뜬 무거운 배치**다. 그럴듯한 메커니즘("lifespan이 막는다")이 코드를 열어보면 반증되는데도 회고에 박제될 뻔했다 — CLAUDE.md task#246의 "원인을 추정으로 귀속하지 말고 대조/계측으로 확정하라"가 **이번엔 내 자신의 회고 기술에** 적용된 사례. 정확한 메커니즘(GIL/이벤트 루프 기아)은 **여전히 미확정**이며, 그렇게 남겨둔다.
- **다음에 다르게 할 것 ②: 배포 후 라이브 스모크는 포트 바인딩을 폴링한 뒤 실행할 것.** `docker ps`가 `Up`이고 로그가 활발해도 API는 닫혀 있을 수 있다.
- **다음에 다르게 할 것 ③: 프로덕션 게이팅 표면의 무쓰기 검증은 in-container 호출을 먼저 고려할 것.** 기존 가토(admin 표면은 테스트 계정으로 라이브 UAT 불가, task#214·215·222·224)의 선택지 3개에 더해, **컨테이너가 자기 env로 스스로 호출**하는 네 번째 수단이 있다. 무쓰기 게이트(검증 통과 여부를 409/422로 가르고 저장은 안 함)와 짝지으면 프로덕션에 흔적을 남기지 않는다.
- **긍정 확인: plan의 "그릴링에서 실측한 사실 (재도출 금지)" 섹션이 제값을 했다.** pydantic 동작(로컬 py3.9 실측)·blast radius·422/409 분기가 전부 박혀 있어 실행이 무마찰이었고, 라이브에서 컨테이너 py3.12/pydantic 2.13.4도 동일함을 확인해 그 실측이 환경을 건너 유효함까지 검증됐다.
- **가용성 사실(기록만, 조치 안 함 — 사용자 판단):** 배포가 배치 예정 시각(`daily_report_us` 07:00 KST · `daily_report_kr` 20:30 KST)에 겹치면 라이브 API가 5분+ 응답하지 않는다. 이번 배포가 정확히 07:00 KST에 떨어져 관측됐다. 배포 빈도가 낮고 충돌이 드물어 후속 태스크로 만들지 않는다.
- **가족 관계:** 이번 건은 "명시적 null이 결측 처리를 통과한다"의 **백엔드판**. 프론트판이 버그리포트 **L3**(`MarketOutlookSection.jsx:17` `Number(null) === 0` → 연도가 `(0)`)로 남아 있다.
