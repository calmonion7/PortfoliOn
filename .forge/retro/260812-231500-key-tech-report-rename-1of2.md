# 2026-08-12 — 주요기술 리포트 개명 + 판 누적(이력) 폐기 + 데이터 센터 등록 (task#299)

fg-loop 드라이브에서 회고 자동 스킵으로 봉인됐고, 2026-08-12 일괄 승급(batch promotion)에서 검토했다.

## 계획 대비 실제

- **계획대로 된 것**: 7슬라이스 전부 랜딩. 4 wave / 7 에이전트, `agents_error: 0` · `empty_result: 0`.
  저장계층(`ON CONFLICT (slug)` + `published_date` 갱신 한 줄)·기동 마이그레이션·라우터 이력 표면 제거·
  프론트 개명·테스트 갱신·문서 동기가 모두 지시 그대로. 배포 후 pytest 1681 / vitest 643 초록,
  라이브 프로브 ALL PASS, 이력 URL 404, `UNIQUE (slug)` 실존. **발산은 낮다.**
- **발산 6건 — 전부 「구현이 틀림」이 아니라 「계획·체크가 달성 불가하거나 느슨했던 자리」다**:
  1. **계획에 없던 파일 2개**(`services/cowork_trigger.py`·`tests/test_cowork_trigger_text.py`). 후자의
     `_POLICY_WORDS = ("enrich", "애널리스트", "선도기술")`은 주석이 아니라 **라이브 가드**(trigger 본문이
     정책명을 열거하지 못하게 막는다 — 「0건 발행」의 근본원인). 개명 후 그 단어가 어디에도 없으므로
     그대로 두면 **가드가 통과하면서도 새 용어를 놓치는 무의미한 감사**가 된다. 착수 전 grep으로 잡아 배정.
  2. **S5의 완료기준이 자기 힘으로 달성 불가였다.** 「전체 스위트 초록」인데 마지막 실패
     (`test_api_doc_sync::test_api_spec_has_no_stale_endpoints`)의 원인 파일 `API_SPEC.md`가 *뒤에 오는*
     S6 단독 소유였다. S5는 비소유 파일 편집 금지를 지켜 `done=false`로 정확히 귀속 보고했고 S6이 해소
     (1680 → 1681).
  3. **C1 체크가 프로브의 *부재 단언*을 지워야 통과하는 모순.** `uat299`는 「선도기술」의 부재를
     단언하므로 그 리터럴을 가질 수밖에 없다(실측 6건 = 부재 단언 3 + 주석 3). 완화가 아니라 **자격으로
     좁히고 sentinel(`grep -c … ≥ 1`)을 추가**해 오히려 엄격하게 만들었다.
  4. **프로브 도장 축이 대상과 독립이었다.** `root.textContent` 전역 매치라 리포트 데이터가 담은
     「(2026-07-13 갱신)」류 문자열(`sources` 제목·`market.as_of`)로도 통과 → 헤더 요소에 묶어 API
     `published_date`와 exact 대조하는 축을 추가(단언 115 → 123).
  5. **「삭제 행 수 > 0」은 원리적 달성 불가였다** — 착수 시 이미 slug당 1행(4행)이라 DELETE는 0건이
     정상. 착수 baseline 실측이 계획 단계에서 이 함정을 제거했고, 완료기준을 **인덱스 실존**으로 잡았다.
  6. **S7a가 프로브 자체 결함 2건을 스스로 잡았다** — `history-gone`이 자기참조라 항상 PASS하는 공허
     단언이었고, `text-clipped`가 `.sr-only`·기존 ellipsis 처리 UI에서 **~150건 거짓 FAIL**을 냈다.
- **부수 손실 1건**: 과도한 C1 때문에 S6이 `.forge/CONTEXT.md`의 「옛 이름은 「선도기술 리포트」」라는
  정당한 역사 서술을 리라이트해 리터럴을 제거했다. **복원하지 않기로 했다** — 현재 문장이 개명 사실과
  기준 확장을 ADR-0038 포인터와 함께 서술하고 ADR 본문(범위 밖)이 옛 명칭을 정본으로 보유한다.
  다만 「체크가 통과하려고 문서를 나쁘게 만든 실례」로 여기 남긴다(가토 ⑧ⓜ③이 이미 경고한 형태).

## 학습

- **다음에 다르게 할 것**:
  - **개명 태스크에서 grep 히트를 「주석/문구」로 일괄 분류하지 말 것.** 파일별로 「이 문자열이 *어떤
    자격으로* 등장하는가」를 한 번 물어라 — 그 안에 *판정 상수*(가드 화이트리스트·enum·정책 단어)가
    섞여 있으면 개명 누락이 감사를 무력화한다. 이번엔 `_POLICY_WORDS` 1건이 그것이었다.
  - **직렬 전체-스위트 슬라이스를 문서 슬라이스보다 *앞*에 두지 말 것.** task#293이 정한 「전체 스위트는
    wave 끝난 뒤 직렬 1회」를 지켰는데도, 그 슬라이스가 문서 슬라이스보다 앞에 오면
    `test_api_doc_sync`처럼 **문서가 고쳐야 할 테스트** 탓에 원리적으로 초록이 안 된다. 순서를 뒤집거나,
    완료기준을 「자기 소유분 초록 + 잔여 실패의 원인 파일 명시」로 쓸 것.
  - **완료기준에 「grep 0」을 쓸 때 그 문자열의 *부재를 단언하는 코드*가 생길 것을 미리 셀 것.** 검증
    코드·반례 문서는 검사 대상 문자열을 포함할 수밖에 없다. 처방은 완화가 아니라 자격 좁히기 + sentinel
    (그 리터럴이 *남아 있어야* 통과하게)이며, 그러면 축이 조용히 삭제되는 것까지 잡는다.
  - **착수 시 baseline 실측이 달성 불가 완료기준을 사전 제거한다.** 이번에 2건을 막았다(「삭제 행 수 > 0」·
    C7의 「실행일」→ 자정 넘김 대비 `>= 날짜`). 정지조건을 못박기 전에 그 수치를 1회 재는 비용은 1분이다.
  - **신규 프로브 축은 결함 주입으로 이빨을 확인할 것** — 신규 모듈의 red-first는 로드 파손이라 단언이
    무엇을 잡는지 증명하지 않는다. 주입은 **같은 디렉터리의 사본**(`cp probe.mjs probe-faultcheck.mjs`)에
    하면 모듈 해석이 보존되고 원본이 깨진 채 남을 위험·「파일당 주입자 1명」 제약이 동시에 사라진다
    (기존 「파일 내 편집→원복」보다 안전 — 승급하지 않고 여기 남긴다).
- **양성 사례 2건**: task#280 회고의 「바뀐 *동작*을 단언하는 축은 첫 수정 *전에* 전 프로브 grep」을 지켜
  `발행` 도장 단언을 미리 훑었고(tech 프로브의 「선도기술」은 전부 1행 주석 = 스테일 0으로 확정). task#293의
  「병렬 wave 완료기준을 자기 소유 파일 표적 테스트로」를 지켜 형제 오염 0.
