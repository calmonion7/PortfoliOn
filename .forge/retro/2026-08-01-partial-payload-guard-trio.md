## 계획 대비 실제

- **계획대로 간 것**: 3슬라이스(earnings 커버리지 임계 · commodities 개별 백필 · kr_sector 업종 백필) 전부 구현, 응답 shape 무변, 프론트·문서 무변경. 전체 스위트 1477 → 1492 passed. 라이브 실측에서 `_mc_save` no-op 패치로 **prod 쓰기 0**을 유지한 채 신규 가드 경로를 실데이터로 통과시켰다.
- **이탈**
  1. **계획의 S1 전제가 사실이 아니었다** — "m7 자신의 실패는 기존 union 가드가 처리한다"고 단정했으나 `if not quarters:`는 `set(m7_by_q) | set(rest_by_q)`라 **둘 다 비어야** 발동한다. M7 전량 실패 + rest 정상이면 분자가 0으로 박제된다. **적대 리뷰가 계획서의 사실 주장을 반증**하고 로컬 재현까지 했다(in-run 수정: 고정 집합엔 완전성 요구).
  2. **"동형 이식"이 함정이었다** — 계획이 `get_treasury()`를 참조 구현으로 지목했는데 treasury는 **백필 → 전량실패 가드** 순서다. 그대로 베꼈으면 완료기준 ②가 원리적으로 달성 불가였다. 착수 시 ⑥ 역산으로 사전 차단하고 판정을 백필 *앞*으로 옮겼다.
  3. 0 나눗셈(`rest_ok / len(rest)`, rest 빈 경우)도 착수 시 역산으로 사전 차단.
  4. S1·S2가 같은 테스트 파일을 써서 병렬 분할을 계획과 다르게(S1+S2 / S3) 잡았다 — 슬라이스 경계 ≠ 병렬 경계.
  5. 에이전트가 주석에 task 번호를 `#254`로 오기(3곳) — 테스트는 전부 초록이고 어떤 게이트에도 안 걸리는 "안 깨지면서 거짓이 된 것".
