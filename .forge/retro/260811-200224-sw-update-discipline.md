# 2026-08-11 — 배포 후 열린 탭이 새 번들을 집어오게 한다 (SW 갱신 규율, task#287)

fg-loop 드라이브가 자동 스킵한 회고의 **유예 승급**(batch promotion, 2026-08-11 일괄). 실행일 2026-08-10 · 커밋 `c1a03d2f`.

## 계획 vs 실제

**계획대로 된 것**

- 훅 신설 + red-first 단위테스트(계획 7종 → 리뷰 반영으로 **9종**), `AppShell` 배선(렌더 영향 0).
- S4(커밋·푸시·빌드)를 메인 세션 단독 구간으로 — `HEAD == origin/main`, 라이브 해시 == 로컬 dist 해시.
- 신규 프로브 **132/132 PASS ×3회**(계획은 2회) 총계·축별 커버리지 완전 일치 · 회귀 게이트 6종 ×2회 **184단언 FAIL 0**.
- **C4 전제를 배포 전에 실증**해 합성 폴백을 제거했다 — 계획이 "가정이므로 대조로 먼저 증명하라"고 못박은 `/sw.js?<쿼리>` 재등록 기법을 옛 번들 위에서 미리 재니 진짜 `controllerchange`가 1회 발화(`firedAt=575ms`). 덕분에 프로브가 합성 `dispatchEvent` 없이 **실메커니즘으로** 게이트됐다.
- 문서 지문 산술을 제3자 검증 가능한 수치로 확인(세 항목이 같은 `navigationStart`, 리로드 직후 문서가 실제로 교체됨).

**일탈**

1. **⭐ 그릴링이 고른 대책의 전제가 사실이 아니었다** — "회귀 프로브 6종이 전부 `serviceWorkers:'block'`이라 OAuth 구멍을 못 잡는다"는 판단으로 훅의 `oauth=` 제외조건을 **정지조건 C2⑦로 못박았는데**, 소스 직독 결과 `useAuthBootstrap`이 코드교환 `fetch` 전에 동기적으로 `history.replaceState`로 search를 지우고 `App.jsx`가 `authLoading` 동안 early-return하므로 **훅이 존재하는 어떤 시점에도 `oauth=`가 남을 수 없다**(도달 불가). 테스트가 `search`를 인위로 세워야만 통과하는 **Goodhart 프록시**였다. **조치가 요점** — 축을 느슨하게 하지 않고 **판정 대상을 재지정**해 축이 7 요구 → 9 존재로 오히려 늘었다. 도달 불가해진 방어 코드는 제거하지 않고 주석으로 사실을 명시했다.
2. **적대적 리뷰 HIGH 3건, 2건은 fault-injection으로 재현** — ① `hadControllerRef` 영구 고착(최초 설치 `controllerchange`를 무시한 뒤 플래그를 안 되돌려 **같은 탭의 이후 진짜 갱신이 전부 무시**됨 — 목표를 정확히 그 코호트에서 무효화) ② 내부 `<Navigate replace>` 오탐(조작 없이 리로드) ③ `oauth=` 죽은 코드(미확증 → 오케스트레이터가 소스로 확정). 「미확증을 `confirmed`로 필터링하지 말 것」이 그대로 값을 했다.
3. **ⓖ 축이 라이브에서 공허하게 통과했다**(프로버 자진 보고) — `initialRedirectRef` 흡수 경로는 4관측 전부 리다이렉트가 최초 무장보다 먼저 끝나 흡수할 것이 없었다. 함의: HIGH②가 겨냥한 창은 **실재하나 라이브 프로브로는 만들 수 없다** → OAuth 안전의 1차 보호는 `initialRedirectRef`가 아니라 **구조적 마운트 게이트**(코드교환 중엔 훅이 아예 없다)이고, 참조는 잔여 협소 레이스의 2차 방어다.
4. **프로브 1차 실행 21 FAIL — 전부 계측 결함, 앱 결함 0건.** 식별자 스냅샷을 nav 렌더 전에 촬영 · **리로드 언로드가 쏘는 진짜 `hidden`**을 자극으로 오인 · 모바일에서 `locator().first()`가 `display:none`인 PC 마스트헤드 사본을 클릭.
5. **실 탭 visibility 전이는 Playwright로 만들 수 없다(대조군으로 확정)** — 3실행모드 × `bringToFront` + `Browser.setWindowBounds` + CDP 5종, **빈 대조 페이지에서도 0건**. bfcache(task#246)에 이은 두 번째 "도구가 원리적으로 못 만드는 상태"다. 이 한계를 **`want=0` 핀 단언**으로 박아 도구가 능력을 얻으면 FAIL하며 승격을 요구하게 했다.
6. **줄번호 시프트를 stale한 숫자에 적용하면 오차를 세탁한다** — `CONVENTIONS.md`가 `.anim-fade` 주석을 `App.jsx:83-84`로 가리켰는데 `git show HEAD~1` 확인 결과 **HEAD~1에서 이미 진실은 85-86**이었다. *문서의 숫자*에 +2를 적용해(→85-86) 옳은 매핑(*실제 코드 위치* old 85-86 → new **87-88**)을 놓쳤고 오차 2줄이 보존됐다. **시프트 보정은 출발 숫자가 HEAD에서 정확했을 때만 타당하다.**

## 배운 것

**다음에 다르게 할 것**

1. **정지조건·판정 대상이 *도달 불가*하면 완화가 아니라 재지정하라.** "그럼 이 위험은 *어디서* 실재하는가"를 다시 묻는 것이 정답이고, 그 결과 축은 대개 늘어난다. → **CLAUDE.md ⑦에 2번째 관측으로 승급.**
2. **브라우저가 사용자 조작으로만 만드는 상태는 자동화가 못 만든다고 먼저 의심하고, 대조군으로 확정한 뒤 `want=0` 핀 단언으로 박아라.** 주석으로만 적으면 도구가 좋아져도 아무도 모른다. → **CLAUDE.md 라이브 UAT 하니스 ⑩으로 승급.**
3. 승급 안 함 — **줄번호 시프트 보정은 출발 숫자의 HEAD 정확성을 먼저 확인하라.** `ed98f72`(fg-map 전체 Refresh) 이후 맵이 심볼·섹션 앵커만 쓰고 줄번호 포인터를 0건 쓰므로 적용 표면이 크게 줄었다(task#290 실측). 포인터가 되살아나면 다시 유효해진다.
4. 승급 안 함 — Cloudflare가 `GET /registerSW.js`(맨 경로)에 이전 빌드 내용을 서빙한다(`immutable, max-age=1y`, `age ~34h`). 앱은 항상 `?<build>`를 붙이므로 **현재는 무해**하나 빌드마다 내용이 바뀌는 경로에 1년 `immutable`은 잠재 함정이고 **실제로 프로브를 한 번 속였다**.
