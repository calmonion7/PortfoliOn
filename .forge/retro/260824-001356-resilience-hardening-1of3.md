## 학습

- **다음에 다르게**:
  1. **리셋·무효화 축을 설계할 땐 「이동」의 *정의*를 열거할 것** — 이 저장소에는 pathname 불변 재네비게이션이 실재한다.
     「결함의 이름이 시야를 좁힌다」(task#273·#328·#331)가 지금까지 *수정 대상 집합*의 이야기였는데,
     이번엔 **계획 작성 시점에 성립 조건의 *정의*가 좁았다** — 같은 가족의 새 표면이다.
     실천: 라우팅·키·리마운트를 다루는 축은 **그 프로젝트에서 「식별자가 바뀌는 방법」을 grep으로 열거**한 뒤 쓸 것
     (여기서는 `navigate(path, {state})` 패턴이 이미 존재했다).
  2. **jsdom + React DEV에서 「1회만 throw」를 부수효과로 흉내내지 말 것.**
     React DEV 모드는 렌더 throw를 **동기 재시도로 한 번 더 호출**하는데(`"React was able to recover by instead
     synchronously rendering the entire root"`), 부수효과(`live.current` 토글) 기반 컴포넌트는 그 2차 호출에서 던지지 않아
     **경계가 한 번도 작동하지 않은 채 테스트가 초록**이 된다. `shouldThrow` prop + `rerender`로 결정적 분기를 쓸 것.
     (「계측 실패를 판정 성공으로 읽기」의 jsdom 픽스처판.) → `frontend/CLAUDE.md`로 승급.
  3. **정지조건 축이 FAIL하면 축의 전제를 먼저 적고 재라.** C1②를 「payload에 `location.search` 0건」으로 썼는데
     옳은 구현이 쿼리 *키*를 뽑기 위해 그것을 정당하게 읽는다(`URLSearchParams(...).keys()`) — **전제가 거짓**이었고
     목표는 달성됐는데 축은 도달 불가였다. 느슨화하지 않고 **등가로 다시 쓰고 이빨을 검증했다**
     (현재 코드 0건 / 수정 전 코드 1건). 기존 #319~321 항목이 이미 다루는 클래스이므로 가토 승급은 하지 않는다.
  4. **폴백 컴포넌트는 컨텍스트에 의존하지 말 것** — `main.jsx` 경계의 폴백이 렌더될 때 `AuthProvider`·`ToastProvider`가
     죽어 있으므로, 폴백이 그 컨텍스트를 쓰면 **폴백 자신이 throw한다.** 이번엔 `Card`/`Button`이 컨텍스트 의존 0이라 안전했고
     메인 세션이 그것을 직접 확인했다(L2 렌즈가 지목한 최고위험 축).

- **확인된 것 (keep)**:
  - **육안 스크린샷을 완료기준에 넣은 것이 값을 했다** — 자동 게이트는 「PNG 생성 + 넘침 0 + 버튼 가시」까지만 재고,
    폴백이 프로젝트 토큰으로 제대로 보이는지는 사람이 봤다. 2뷰포트 캡처가 산출물로 남았다.
  - **적대 검토가 diff 리뷰로는 원리적으로 안 보이는 것을 잡았다** — HIGH·LOW 둘 다 vitest·빌드 초록 상태로 통과했다.
