# 심층 리포트 용어 링크 확대 2/2 — 심층 리포트 어휘를 주식 용어집에 추가

## 목표 / 비목표
- 목표: 주식 용어집(`frontend/src/glossary/terms.js`, 현재 85개 — 시장·기술지표 편중)에 심층 리포트가 실제로 쓰는 어휘를 더해, 10건 전체에서 매칭되는 **서로 다른 용어 20종**을 늘린다. 두 묶음:
  - **(가) 본문 빈출 재무 용어**(dev 10건 실측 빈도): GAAP/Non-GAAP(28) · 재무제표 재작성(17) · 감가상각(14) · 영업현금흐름/현금흐름(21) · 주주환원(11) · 희석(10) · 매출총이익(률)(13) · 레버리지(10) · CapEx/설비투자(13) · 계약부채(6) · 순현금(5) · 차입금 · EBITDA(5, 단독) · 런레이트(3) · 감사의견(4).
  - **(나) 심층 리포트 고유 계산 개념**: 런웨이 · 손익분기 금리 · 이자보상(→ 기존 `이자보상배율`에 **별칭**으로, 새 항목 아님) · 이익수익률 · 무위험 금리 · 한계 분배율 · 평균 분배율 · 배수비 · 약정 증가 배수 등 `VALUE_META` 라벨·게이지 변수명. **사전 추가 + 그 라벨에도 배선**: `ComputedBlock`의 `VALUE_META[k].label`, `FlipGauge`의 `variable`.
- 비목표:
  - **업종·제품 고유명사 제외**(D램·HBM·THAAD·Mounjaro·USDC 준비금 등) — 주식 용어가 아니라 [[주요기술 리포트]]의 영역.
  - **bp 제외** — `match.js`의 라틴 경계 규칙이 앞 숫자를 막아 「+100bp」에 원리적으로 안 걸린다. 매처 규칙은 바꾸지 않는다.
  - 매처(`match.js`) 규칙 변경 없음.
  - 1/2의 필드 배선(선행 파트).

## 정본
- 용어: `.forge/CONTEXT.md` 「주식 용어집」 · 「심층 리포트」 · 브랜치 오버레이 「렌즈」·「구조 축」
- 관련 ADR: 없음
- **(나)의 정의문은 `backend/services/analyst_lenses.py`의 계산식이 정본이다** — 화면 설명이 서버 공식과 어긋나면 안 된다(예: `lens5` docstring 「equity: 런웨이 · deposit: 손익분기 금리 여유 · debt: 이자보상」, `lens8` 「이익수익률 vs 무위험 금리」, `lens4` 「한계 분배율 Δ연동비용 ÷ Δ매출」). 정의문 작성 시 해당 함수를 읽고 공식을 일반인 말로 옮길 것. (가)는 일반 재무 정의.
- 정의문 검토는 중간 확인 없이 **main 머지 단계(사람)**에서 한다 — dev push는 dev 스택만 바꾼다.
- 완료 정의(DoD):
  1. `cd frontend && npx vitest run src/glossary/match.test.js` — 신규 용어 **각각**에 대해 dev 10건에서 뽑은 실제 문장 1개로 매칭 단언 + 부분 문자열 오매칭 가드(한글 키는 substring 매칭이라: 예 `차입금`이 `순차입금` 안에서 어떻게 잡히는지, `희석`·`상각`이 의도치 않은 단어 안에서 잡히지 않는지 — 실제 문장으로 확인한 것만 단언). **red 선행**: 신규 단언은 작성 시점에 실패해야 한다(전진 검사).
     - 작성 시점 사전 상태: `match.test.js`+`AnalystReport.test.jsx` 58건 통과.
  2. `npx vitest run src/pages/AnalystReport.test.jsx` — 서버 계산 라벨(`런웨이` 등)과 게이지 변수명에 `.glossary-term` 버튼이 렌더된다(red 선행).
  3. **게이지 배선 제약**: `FlipGauge` 루트가 `role="img"`라 그 안의 버튼은 접근성 트리에서 프루닝된다(live-uat-probes 「AT 프루닝」 클래스). 변수명 링크를 넣으려면 `role="img"`·`aria-label`을 트랙 영역으로 좁혀 머리 줄을 그 밖으로 뺄 것 — 판정: 프로브에서 게이지 변수명 버튼이 `page.getByRole('button', { name: <변수명> })`로 잡힌다.
  4. dev 스택(127.0.0.1:8084) — dev push 후 10건 각각 「모두 펼치기」 상태에서 `.glossary-term:not(.lens-help)`의 **서로 다른 텍스트(용어) 종류 수**를 10건 합집합으로 센다. 사전 상태(1/2 완료 후 예상): **≤20종**(노드 실측은 미배선 제목까지 포함한 전 필드 기준이라 상한 — S4 착수 시 dev에서 실측해 확정할 것. 영업이익·컨센서스·가이던스·순이익·EPS·자사주 매입·수주잔고·FCF·PER·배당·QoQ·목표가·수급·시가총액·영업이익률·내부자·YoY·IPO·부채비율·밸류에이션). 판정: **≥ 20 + 추가한 용어 중 10건에 실제 등장하는 수**(추가 시점에 노드로 재계산해 run.md에 정확한 기대값을 적고 일치 단언).
     - 「이 단언이 통과하면서도 깨질 수 있는 방식」: 종류 수는 늘었는데 정의문이 서버 공식과 다를 수 있다 → (나) 정의문마다 run.md에 근거 함수·줄을 1줄씩 적는다. 그리고 longest-match가 기존 용어를 가로채 링크가 **줄어드는** 경우(예: 새 긴 키가 `영업이익`을 삼킴) → 1/2의 접힌 계수 104가 줄지 않았는지 함께 확인(감소분이 있으면 그 용어가 더 정확한 쪽인지 판정해 기록).
  5. 3뷰포트(m278·m390·pc1440) 육안 스크린샷 — 특히 `ComputedBlock` 값 그리드 라벨과 게이지 머리 줄.
