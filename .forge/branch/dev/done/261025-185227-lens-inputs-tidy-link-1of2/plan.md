# 렌즈 원자료 목록을 항목별 「직전 → 현재」로 묶고 순서를 고정한다

## 목표 / 비목표
- 목표: 심층 리포트 렌즈 상세의 「출처 보기 · 원자료 N건」을 펼쳤을 때, 같은 항목의 직전·현재 값이 한 묶음으로 나란히 보이게 한다. 순서는 늘 같아야 한다.
- 원인(조사 확정):
  - `frontend/src/components/reports/LensReport.jsx`의 `InputsTable`은 `Object.entries(inputs)` 순서대로 그린다.
  - 그런데 원자료는 PostgreSQL **jsonb**에 저장된다. jsonb는 키를 **글자 수가 짧은 것부터** 다시 정렬한다. 그래서 루틴이 보낸 순서와 무관하게 `고정비(현재)·고정비(직전)·기여몫(현재)·기여몫(직전)`처럼 현재가 직전보다 먼저 나왔다(사용자 스크린샷 2026-10-25, 렌즈 3).
- 결정(fg-ask 2026-10-25):
  - 분류 방식은 **항목별 「직전 → 현재」 묶음**이다. 묶음 제목은 항목 이름(`기여몫`)이고, 아래에 `직전`·`현재` 하위 행을 두며, 하위 행마다 값·출처 배지·출처 글·근거를 보인다.
  - `_prev`/`_curr` 짝이 없는 항목(`cash`·`annual_burn`·`forward_earnings` 등)은 하위 행 없이 한 줄로 보인다.
  - 출처별 분류(공시/애널/추정 제목)와 열 정렬만 하는 안은 채택하지 않았다.
- 구현 방침(질문하지 않고 정함):
  - 항목 순서는 `INPUT_LABELS`에 정의된 키 순서를 따른다. 정의에 없는 키는 맨 뒤에 키 이름 순으로 둔다. 서버나 jsonb의 순서에는 기대지 않는다.
  - 묶음 제목은 `INPUT_LABELS[k]`에서 `(직전)`/`(현재)`를 떼서 만든다. 새 라벨 표는 만들지 않는다.
  - 원자료 값 행은 계속 `li` 하나씩이다. 기존 테스트 `AnalystReport.test.jsx:776`이 `details li`로 `평균 몫` 행을 찾기 때문이다.
  - UIUX 기준선: 기존 토큰(`smallCap`·`--text-2`·`Badge`)만 쓰고, 간격은 4/8 배수로 맞춘다. 360px에서 넘치지 않아야 한다.
- 비목표:
  - 원문 링크(2/2의 몫).
  - 백엔드·저장 순서 변경.
  - 민감도 표·사례 행·게이지의 출처 표시.
  - 펼침 상태 기억.
