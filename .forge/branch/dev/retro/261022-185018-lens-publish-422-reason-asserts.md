- 어긋난 것:
  - **루프 C1 판정 문구가 원리적으로 달성 불가였다.** 계획 DoD 1의 「가드를 넣으면 +1」을 두 파일만 도는 명령의 `passed ≥ 175`로 옮겼다. 그런데 가드를 선례(`test_no_print.py`)처럼 별도 파일에 두니 그 명령은 174에서 멈췄다. 명령에 가드 파일을 더해 정정했고, 하한 175는 유지했다(두 파일에서 1건만 지워도 FAIL).

## 배운 점
- 다음엔 다르게 할 것:
  - **「+N개」 완료기준은 그 N개가 사는 파일까지 판정 명령이 덮는지 계약 시점에 확인할 것.** 새 테스트를 별도 파일에 둘지는 실행 중에 정해지므로, 기준을 「명령 X의 passed ≥ k」로 쓰면 구현 선택 하나로 도달 불가가 된다. 「대상 파일 회귀 0 + 신규 가드 파일 통과」로 나눠 쓰는 편이 안전하다.
  - **이빨 검사의 판정 단위는 테스트가 아니라 응답으로 셀 것**(→ verification-gates 승급). 같은 주입 실행에서 테스트 단위 「뿐」 기준은 1개, 「하나라도」 기준은 2개를 남겼다. 섞인 케이스는 테스트 단위에선 보이지 않는다.
  - **심기 검사는 가드와 심는 대상을 다른 파일에 두고 가드 파일만 돌릴 것**(→ verification-gates 승급). 같은 파일이면 심은 함수 자체가 실패해 이빨이 없어도 빨강이 나온다.
  - **노출 규모는 정적으로 세지 말고 주입해서 잴 것.** 「상태코드만 보는 33개 중 32개 노출」은 실제로 6테스트였다. pydantic이 항목 검증 실패 시 리스트 길이 검사를 생략해, 필드 오류·`LensIn` 검증기는 주입 뒤에도 목표 사유가 그대로 나온다. 노출은 본문 단위 검증기와 HTTPException뿐이다(이미 `tests/CLAUDE.md`에 반영).
  - 공유 헬퍼는 약한 사용을 API 모양으로 막을 것. `assert_rejected`는 목록 detail에서 `loc`만 주면 실패하고, `loc`은 완전 일치로 본다(`('body',)` 접두 일치가 모든 오류에 맞는 것을 차단).
  - `git mv -k`는 미추적 파일에 무음 no-op이다. forge 상태 파일(미추적)을 옮길 땐 `mv`를 쓰고 결과를 `ls`로 확인할 것.
