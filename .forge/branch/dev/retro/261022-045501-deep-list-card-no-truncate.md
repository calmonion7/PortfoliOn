## 배운 것
- 다음엔 다르게:
  - **계획에 뷰포트를 적을 땐 그 프로브의 `run(...)` 목록을 같이 grep해 대조한다.** 계획의 폭 집합과 프로브의 폭 집합이 다르면 그 축은 「계획한 폭에서 재지 않는」 축이 된다.
  - **잘림처럼 성분이 둘인 축(스타일 선언 vs 실제 넘침)은 detail에 성분별 개수를 따로 찍는다.** 판정은 OR로 묶어도 되지만 숫자는 분해해야 회고·계획 수치로 인용할 수 있다(live-uat-probes 성분 분해 규칙의 사례).
  - **구조가 바뀌는 시각 변경의 프로브 축은 요소를 텍스트(API가 준 값의 leaf)로 찾는다.** DOM 구조로 찾으면 옛 구조에서 축이 돌지 않아 red-first가 불가능하다 — 이번엔 2행→3행 변경에도 같은 축이 옛 코드에서 돌았다.
  - (승급 보류, 1건) **red-first에서 원래 통과하는 축(정렬)의 대조군을 일회성 `CONTROL=` 환경변수가 아니라 매 실행 자동 단언으로 넣었다**(마진 10px 주입 → 편차 > 0.5여야 PASS → 원복). 이빨이 매 실행 재증명된다. 같은 방식이 한 번 더 쓰이면 live-uat-probes ⓤ에 승급한다.
