## 계획 대비 실제
- 계획대로 된 것: 재무 15종 + 계산 8종 + `이자보상` 별칭, `ComputedBlock` 라벨·`FlipGauge` 변수명 배선, 게이지 `role="img"` 범위 축소. 정지조건 C4·C5 통과(신규 16/16, 기존 22종 보존, 접힌 계수 10건 전부 증가·감소 0), 전체 vitest 1132. 같은 루프의 1/2(task#399)는 계획서가 노드로 미리 잰 접힌 계수 104가 dev 10건 **정확히 일치** — 승급할 교훈 없음(회고 파일 없이 검토만).
- 어긋난 것:
  - **DoD 3(「게이지 변수명 버튼이 `getByRole`로 잡힌다」)이 이빨 없는 판정이었다.** 대조군 `<div role="img"><button>안</button></div>`를 Playwright `getByRole`·`getByText`·`ariaSnapshot()`, Chromium CDP `getFullAXTree` **넷 다 그대로 노출**했다 — 고치기 전에도 통과했을 축이다. 구조 축(`[role="img"]` 안 인터랙티브 0)으로 판정을 바꿨다.
  - 계획의 어휘 목록 중 **Non-GAAP·CapEx는 dev 10건에 0회** — Non-GAAP 제외, CapEx는 `설비투자` 별칭으로. 대신 dev 11회인 일반 `현금흐름`을 추가.
  - 같은 낱말이 리포트 안에서 **사전과 다른 뜻**으로 쓰였다 — 「희석」은 전부 희석주식(diluted shares), 「레버리지」는 전부 고정비(영업) 레버리지. 정의문을 실문장 기준으로 다시 썼다.
  - 계획 DoD 4의 「종류 수 ≥ 20 + N(N은 추가 시점에 노드로 재계산)」 대신 정지조건 C5의 **정체성 판정**(신규 16종 각각 · 기존 22종 보존)을 썼다 — 기대값을 실행자가 스스로 정하는 형태를 피했다.

## 배운 점
- 다음에 다르게 할 것:
  - **접근성 축은 착수 시 대조군 1회로 하니스의 이빨부터 잰다.** 「AT에서 잡힌다/안 잡힌다」를 Playwright·Chromium으로 판정하는 완료기준을 보면, 같은 하니스로 「틀린 구조」 대조군을 먼저 돌려 구별되는지 확인할 것(이번엔 구별 안 됨 → DOM 구조 축).
  - **용어집 정의문은 dev 실문장을 먼저 뽑고 쓴다.** 필드 경로 + 앞뒤 문맥을 뽑는 1콜(리포트 JSON 순회)이 「없는 용어」(0회)·「다른 뜻」을 둘 다 드러냈다. 계획에 어휘 목록이 있어도 그 목록 자체를 baseline으로 반박할 수 있게 S0에 둘 것.
  - **새 긴 키는 기존 용어를 가로챌 수 있으니 가드 단언을 쌍으로** — 잉여현금흐름(FCF)·EV/EBITDA·이자보상배율이 새 키(현금흐름·EBITDA·이자보상)에 먹히지 않음을 실문장으로 못박았다(`match.test.js` task#400).
  - fg-loop 정지조건을 고정하기 전 「목표 용어가 *배선되는 필드*에 실재하는가」를 dev JSON 경로로 확인해 제목 전용 용어를 걸렀다 — verification-gates #344(목표값 도달 가능성)의 양성 적용 사례.
