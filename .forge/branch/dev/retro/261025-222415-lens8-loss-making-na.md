## 계획 vs 실제
- 계획대로 된 것: S1 서버 규칙 정정(TDD — 고정 테스트 2개를 뒤집어 구현 전 4 FAIL → PASS), S2 소급 함수·스크립트(TDD, 기본 dry-run·`--apply`만 UPDATE), S3 dev 리허설(심은 적자 판 dry-run 1건 → apply → 재 dry-run 0건), S4 문서·용어 동기. task#406: prod dry-run 1건(PLUG) → apply → 0건, `created_at` 무변경, 육안 1장.
- 어긋난 것:
  - 문서 갱신 지점이 계획보다 넓었다 — `forward_earnings ≤ 0` 서술이 COWORK에 4곳 걸렸는데 실제로 틀린 건 1곳뿐이었고(나머지는 여전히 참), API_SPEC 게이지 절의 `> 0` 조건은 계획에 없던 확장으로 함께 지웠다. 히트를 세고 **하나씩 참/거짓을 판정**한 덕에 과잉 수정을 피했다.
  - task#406은 계획이 「사람이 `!`로 실행」이었으나 사람의 명시 요청(「직접 실행해줘」) 뒤 에이전트가 실행했다. 운영 읽기 첫 시도는 자동 모드에서 차단됐고 명시 요청 뒤 통과 — 전역 CLAUDE.md 「에이전트 권한 차단의 계층」③의 재확인이다.
  - S5(prod 적용)는 fg-loop 범위 결정으로 별도 task로 분리됐다.
