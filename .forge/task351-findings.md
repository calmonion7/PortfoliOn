## 2. 열람 계측은 완전한가 — **아니다 (「9」는 하한이다)**

계획서가 스스로 지목한 전제 「실측 3은 user_events 계측이 완전하다는 전제에 기댄다」의 판정이다.

**`report_view_open`을 쏘는 지점은 전수 1곳이다:**

| 파일 | 줄 | 맥락 |
|---|---|---|
| `frontend/src/pages/Reports.jsx` | `openDetail` | 리포트 탭 상세 진입 (목록 클릭) |

- 그 한 함수가 리포트 탭의 **단일 관문**이라 그 화면 안에서는 **완전하다** — 추천 탭 딥링크도
  같은 `openDetail`을 거친다(`Reports.jsx`의 `initialTicker` 이펙트).
- **그러나 종목 단위 분석을 보는 다른 화면들은 아무 이벤트도 쏘지 않는다:**
  - `/analyst-report/:ticker/:date` (심층 리포트 상세) — `trackEvent` 호출 **0건**
  - 포트폴리오 대시보드 카드 — 종목 단위 이벤트 없음
  - 랭킹 행 클릭은 `ranking_row_click`(다른 이름)이고 30일간 **0건**이다
- ticker를 싣지 못한 `report_view_open`은 **0건**이고, ticker가 실린 *모든* 이벤트의 합집합도 **9**다.

**판정** — 9는 「리포트 탭에서 열린 종목 수」로는 정확하지만, **「사용자가 실제로 본 종목 수」로는 하한**이다.
차이가 얼마인지는 **현재 데이터로 알 수 없다**(관측 자체가 없다).

**결정에 주는 함의** — A안 ⓑ(열람 이력 기반 선별)를 지금 데이터 위에 세우면, 심층 리포트로만 보던
종목이 「아무도 안 본 종목」으로 분류돼 갱신에서 빠진다. ⓑ를 고르려면 **계측을 먼저 메우는 것이
선행 조건**이다(심층 리포트 상세에 `report_view_open` 상당의 이벤트 추가). 계측 없이 ⓑ를 고르는 것은
**측정하지 않은 것을 0으로 읽는** 것이다.

## 3. enrich 부분 갱신은 가능한가 — **가능하다**

- 라우터 `stocks.py::enrich_single` — `model_dump(exclude_none=True)` 후 `v is not None`으로 한 번 더 거른다.
  **보내지 않은 필드는 저장 계층에 도달하지 않는다.**
- 저장 `storage/portfolio.py::enrich_stock` — `SET` 절을 **받은 키로만** 조립한다. 전 필드 치환이 아니다.
- **라이브 증거** — `enrich_history` 612행 중 `changed` 길이가 8 미만인 행이 **131건**이고,
  그중 정확히 1개 키만 건드린 **130건 전부**가 나머지 필드 7개 이상을 **비-null로 보존**하고 있다.

→ **C안(필드별 차등 갱신)의 API 게이트는 열려 있다.**

### 3.1 회귀 테스트로 못박음 — `backend/tests/test_enrich_partial_update.py` (4축)

이 결론이 조용히 뒤집히지 않도록 계약을 테스트로 고정했다. **기존 스위트는 이걸 못 지켰다** —
`test_storage.py`의 기존 enrich 테스트들은 컬럼의 **존재**만 단언하고 **부재**는 아무도 단언하지
않아서, 구현을 전 필드 치환으로 바꿔도 초록으로 통과했다.

| 축 | 단언 | 이빨 확인 (주입 → 실제 FAIL) |
|---|---|---|
| (a) 음성 | 1필드 전송 시 나머지 7개가 SET 절에 **없다** | `enrich_stock`을 전 필드 치환으로 주입 → **FAIL** |
| (b) 양성 | 8필드 전송 시 **전부** SET 절에 있다 | 대조군 — (a)가 「대상에 닿았음」을 증언하게 한다 |
| (c) 라우터 필터 | `"risks": null`은 저장 계층에 **도달하지 않는다** | 라우터의 null 필터 제거 주입 → **FAIL** |
| (d) 이력 계약 | `enrich_history.changed`가 **보낸 키만** 담는다 | 전 필드 치환 주입 → **FAIL** |

구현이 이미 옳아 red-first가 원리적으로 불가하므로, 대신 **일시 주입으로 이빨을 확인하고 원복**했다
(주입 후 `git diff` 0 · `INJECTED` 잔존 0건 확인). (d)가 필요한 이유는 위 「라이브 증거」 쿼리가
**`changed`의 의미에 의존**하기 때문이다 — `changed`가 전 필드를 담도록 바뀌면 그 쿼리가 조용히
다른 것을 세게 된다.

⚠️ **다만 「가능하다」와 「그렇게 하고 있다」는 다르다.** 야간 전량 경로는 현재 8필드를 **함께** 보낸다
(`changed` 길이 8이 481행). C안을 채택하면 바꿔야 하는 것은 API가 아니라 **루틴이 무엇을 보내는가**다.

## 4. 매일 돌리면 무엇이 바뀌는가 — 표현만이 아니라 **사실도** 바뀐다

계획서가 지목한 전제 「실측 5의 유사도는 텍스트 유사도이지 의미 유사도가 아니다」의 판정이다.

### 4.1 기계 측정 — 두 지표를 함께 냈다

연속일 쌍 **268쌍** · 비교된 필드 인스턴스 **2143건**(표본 하한 100 충족)에 대해,
ⓐ **텍스트 유사도**(단어 단위)와 ⓑ **사실 중첩도**(숫자·퍼센트·라틴 토큰 집합의 Jaccard)를 함께 계산했다.

| 필드 | ⓐ 텍스트 | ⓑ 사실 | n |
|---|---|---|---|
| `market_outlook` | 0.749 | **0.789** | 267 |
| `moat` | 0.514 | 0.546 | 268 |
| `key_resource` | 0.498 | 0.465 | 268 |
| `competitor_edge` | 0.457 | 0.443 | 268 |
| `insights` | 0.441 | 0.398 | 268 |
| `risks` | 0.440 | 0.427 | 268 |
| `growth_plan` | 0.390 | 0.465 | 268 |
| `recent_disclosures` | 0.291 | 0.354 | 268 |
| **전체** | **0.472** | **0.486** | 2143 |

신뢰성 계측: identity 대조군 **4270/4270**(사실 토큰화 정상) · 사실 토큰이 없어 정의역 밖인 인스턴스 **2건** ·
한쪽에만 사실 토큰이 있는(= 사실이 생기거나 사라진) 인스턴스 **12건**.

> ⚠️ **계획서의 유사도 수치와 직접 비교하지 말 것** — 계획서는 다른 계산 방식을 썼고 여기는 단어 단위다.
> 절대값이 아니라 **ⓐ와 ⓑ의 관계**를 보라.

**읽는 법과 그 결과** — 당초 가설은 「ⓑ가 높은데 ⓐ가 낮으면 같은 사실을 다시 쓴 것」이었다.
실측은 **ⓐ ≈ ⓑ**(0.472 vs 0.486)로, **그 가설이 그대로는 성립하지 않는다**:
표현이 바뀌는 만큼 **사실 토큰도 같이 바뀐다.** 즉 매일의 재작성은 단순한 재표현이 아니다.

구조화 필드인 `market_outlook`만 양쪽 모두 뚜렷이 높다(0.75/0.79) — 형식이 값을 고정하기 때문이고,
이는 「구조를 주면 안정된다」는 방향을 지지한다.

### 4.2 눈으로 대조 — 기계 수치가 못 보여주는 것

`moat`·`key_resource`를 3종목에 대해 연속 두 판 나란히 읽었다. **두 양상이 확연히 갈린다.**

**ⓐ 안정형 (AAPL)** — 두 판이 거의 같은 글이고, 달라진 것은 ⓘ 자기수정 한 군데 제거
ⓘⓘ **진짜 신규 사실 하나 추가**(「2026년 9월 공개된 A20 Pro(2nm)」)였다.
이건 재작성이 **값을 더한** 경우다.

**ⓑ 불안정형 (005930)** — 두 판이 **같은 항목을 두고 서로 다른 말을 한다:**

| | 09-13 판 | 09-14 판 |
|---|---|---|
| HBM 지위 | 「HBM4 세대 점유율은 **28% 수준의 2위**로 추정」 | 「**HBM4 세계 최초 양산 출하**(2026년 2월)로 … 구도를 되돌렸고, 글로벌 HBM 점유율이 1분기 21%에서 2분기 **33%**로」 |
| 해자의 근거 | 「해자의 폭은 캐파와 수직계열화에서 나오지 **세대 선점에서 나오지 않는다**」 | 「HBM4 **세계 최초** 양산 출하로 … 밀렸던 구도를 되돌렸다」 |

하루 간격의 두 판이 **2위인지 최초인지**를 반대로 말한다. 어느 쪽이 옳은지는 이 조사의 범위가 아니다 —
**결정에 중요한 것은 「연속 재생성이 서로 모순되는 판을 만든다」는 관측 자체**다.

> ⚠️ 부수 관측(검증하지 않음) — 005930 09-13 판의 분기 실적 수치(매출 171.5조원·영업이익률 52.2%)는
> 이 회사의 통상 규모와 크게 어긋나 보인다. **이 조사는 외부 사실을 검증하지 않았으므로 단정하지 않는다.**
> 다만 「재작성이 오류를 새로 들여올 기회」라는 계획서 실측 6을 뒷받침하는 정황이다.

**결정에 주는 함의** — 「매일 갱신」의 대가는 비용만이 아니라 **판의 불안정성**이다. 반대로 「덜 자주」의
대가는 신선도다. B안은 이 둘의 교환이고, §4.1의 `market_outlook` 결과는 **구조화가 그 교환을 완화한다**는
제3의 방향을 가리킨다.

## 6. 재현 방법

```bash
# 수치가 지금도 맞는지 (독립 2소스 대조: 디스크의 JSON ↔ 라이브 DB 재산출)

# 이 문서가 현재값을 담고 있는지
backend/.venv/bin/python scripts/task351_measure.py --verify-docs

# 부분 갱신 보존의 라이브 증거 (§3)
docker exec portfolion-postgres-1 psql -U portfolion -d portfolion -tAc "
SELECT count(*) FROM enrich_history h
WHERE jsonb_array_length(h.changed)=1
  AND (SELECT count(*) FROM jsonb_each(h.fields) e WHERE e.value <> 'null'::jsonb) >= 7;"
```

⚠️ 전부 **읽기 전용**이다. 이 조사는 라이브 DB에 아무것도 쓰지 않았다.
