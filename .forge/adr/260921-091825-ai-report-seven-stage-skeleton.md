# AI 작성 문서의 읽는 순서는 공통 7단 뼈대를 따른다 — 심층 리포트만 증권사 형식 예외

- 상태: 채택 (Accepted)
- 관련: task#358·#359(적용), ADR-0027(심층 리포트 = 증권사 리포트 표준 구성), ADR-0047(리포트 계열 표시 통합 — 종목 축 1:N 병합·기술 N:M 연결), ADR-0043(기술↔종목 역방향 연결 인덱스), `CONTEXT.md`「7단 뼈대」·「리포트」·「심층 리포트」·「주요기술 리포트」

## 맥락

외부 AI([[루틴]])가 쓰는 문서 표면이 셋으로 자랐다 — 리포트 상세의 **사업분석 탭**(enrich 필드 9섹션, 그룹 헤더 4개), **심층 리포트**(발행물, 증권사 형식), **주요기술 리포트**(기술 단위 발행물, 장 9개·플로팅 항해 바 4장). 각자 다른 사이클에서 섹션이 덧붙여져 **읽는 순서가 세 가지**가 됐고, 사업분석 ↔ 심층 사이에 겹치는 자리(헤더 진입 칩 2종 ↔ 탭, 컨센서스, 리스크)가 생겼으며, 종목 공통 문서인 기술 리포트는 사업분석 본문에서 닿을 길이 없었다(헤더 칩만).

## 결정

1. **사업분석 탭과 주요기술 리포트는 같은 7단 뼈대로 읽는다** — 「결론 → 시장 → 경쟁 → 우위 → 전망 → 리스크 → 확인할 것」. 단 이름 7개를 **그룹 헤더로 두 표면에 동일 표기**한다(결론 단은 헤더 없이 최상단). 사용자가 「통일」을 느끼는 수단은 같은 단어가 같은 순서로 두 화면에 보이는 것뿐이다.
2. **심층 리포트는 예외** — 증권사 리포트 표준(투자의견·적정주가 → 논지 → 투자 포인트 → 밸류에이션 → 실적 추정 → 리스크)이 그 문서의 정체성이다(ADR-0027). 순서를 7단으로 바꾸면 「증권사 리포트처럼 읽힌다」는 가치를 잃는다. 대신 임베드(리포트 상세 탭) 시 **컨센서스 근거 섹션을 기본 접고**(데이터 보존·펼치기 가능), 리포트 상세 헤더의 「애널리스트 리포트 →」·기술 칩 2종은 **제거**한다(탭과 본문 섹션이 대신한다 — 같은 목적지가 두 번, 그리고 옛 이름).
3. **사업분석의 「경쟁」 단에 「관련 기술」 섹션**을 둔다 — 기술 인덱스(ADR-0043 `GET /api/tech-reports/index`)만으로 기술별 한 행(이 종목의 단계·선두 격차·참여 업체 수 → 리포트/해부 링크). 추가 fetch·스키마 변경 없음. 기술 리포트 쪽은 대칭으로 「구성과 연관」 장을 경쟁 단 마지막에 둔다 — 두 표면이 같은 자리에서 서로를 가리킨다.
4. **기술 리포트의 플로팅 항해 바는 4장 유지**(개요 · 시장·경쟁 · 진척·리스크 · 근거) — 바는 거친 점프(모바일 폭에 칩 4개), 본문 그룹 헤더는 7단+근거의 세밀한 구획. 장이 단을 **포괄하도록** 매핑을 정리한다(개요=결론 / 시장·경쟁=시장·경쟁·우위 / 진척·리스크=전망·리스크·확인할 것 / 근거). 계열 비교·구성과 연관은 「개요」장에서 「시장·경쟁」장으로 옮긴다.
5. **리스크는 양쪽에 남긴다** — 사업분석 리스크(enrich, 매일 갱신)와 심층 리스크 요인(발행 시점 박제)은 as-of가 다른 정당한 공존이다(ADR-0047이 확정한 규약). 사업분석 리스크 섹션에 「발행 시점 리스크 요인은 심층 리포트 →」 한 줄만 둔다.

## 고려한 대안

- **세 표면 전부 7단으로** — 심층 리포트의 투자의견·밸류를 「결론」 자리로 옮기는 것. ADR-0027 개정이 필요하고 증권사 형식이라는 문서 정체성을 잃는다. 기각.
- **기술 리포트 장을 7단+근거 8개로 교체** — 위계가 하나라 단순하지만 플로팅 바 칩이 8개가 되어 m278에서 여러 줄로 접힌다(칩 34px 핀, `frontend/CLAUDE.md`). 기각.
- **사업분석 리스크를 심층 있으면 숨김** — enrich가 매일 갱신하는 최신값을 발행 시점 값으로 후퇴시킨다. 기각(wrong<missing의 역방향 — 최신을 지우는 것도 손실).
- **관련 기술에 시장 요약 인라인** — 기술별 추가 fetch가 필요하고 사업분석의 시장 전망 섹션과 중복된다. 기각.

## 결과

- 그룹 헤더 이름·순서가 두 표면의 **계약**이 된다 — 한쪽에 섹션을 추가할 때 7단 중 어디에 속하는지를 먼저 정한다. 어디에도 안 들어가면 뼈대를 개정하는 것이고 이 ADR을 개정한다.
- 기술 리포트의 `SECTIONS[].chapter` 매핑이 바뀌므로 장 순서를 단언하는 테스트·라이브 프로브(uat276~uat321 계열)가 갱신 대상이다 — 선재 FAIL을 프로브에 수입하지 말고 baseline 이상으로 판정한다(CLAUDE.md 「항상 FAIL하는 축은 게이트가 아니다」).
- 헤더 칩 제거로 `uat212`의 `hasEntryLink`·`uat-tech-exposure`의 `header-tech-chip` 축이 대상을 잃는다 — 탭·본문 섹션으로 옮긴다.
