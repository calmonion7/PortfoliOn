# 0036 — 인증된 `/api/*` 응답은 Service Worker 런타임 캐시에 담지 않는다

- 상태: 채택 (Accepted)
- 날짜: 2026-08-10
- 관련: task#290(B44·B45·B46·B47 사용자 경계 4건), B47(`.forge/codebase/CONCERNS.md` §7.6·§0), task#287(SW 갱신 규율 — 새 SW 활성화를 담당), ADR-0029(공개 read 없음 — 같은 장르의 전면 금지 규칙)

## 맥락 (Context)

`frontend/vite.config.js`의 VitePWA `runtimeCaching`이 `/api/auth/*`를 제외한 모든 `/api/*` GET을 `NetworkFirst`로 캐시했다 — `cacheName: 'api-cache'`, `maxEntries: 50`, `maxAgeSeconds: 300`, `networkTimeoutSeconds: 10`.

**Workbox는 URL만으로 캐시 키를 잡는다.** `api.js`가 주입하는 `Authorization` 헤더는 키에 들어가지 않고 `Vary` 처리도 없다. 즉 같은 URL이면 **어느 사용자의 응답이든 같은 한 항목**이다. 그리고 `App.jsx::doLogout`은 `localStorage`만 지운다(`grep -rn "caches\." frontend/src/` = **0건**).

도달 경로: 사용자 A 로그아웃 → 5분 내 같은 브라우저에서 B 로그인 → `/api/portfolio`·`/api/stocks`·`/api/stocks/dashboard` 중 하나가 실패하거나 10초 타임아웃을 넘기면 **A의 보유종목이 B에게 서빙된다.** `/api/auth/*`가 캐시에서 제외돼 있어 **신원은 B로 맞고 데이터만 A인** 최악의 조합이 된다.

같은 규칙이 부수로 **무표시 stale 시세**도 만든다. 10초 타임아웃 폴백이 최대 5분 된 가격을 주는데, `PriceFreshness`가 읽는 `lastUpdated`는 `usePortfolioData`가 **클라이언트 수신 시각**으로 찍은 값이라 5분 된 가격이 "방금"으로 표시된다.

## 결정 (Decision)

`/api/*` 런타임 캐시 규칙을 **제거한다.** Service Worker는 앱 셸(정적 자산)과 폰트만 캐시하고 **인증된 API 응답은 캐시하지 않는다.**

규칙 제거만으로는 이미 사용자 기기에 저장된 `api-cache` 저장소가 남는다(Workbox `cleanupOutdatedCaches`는 precache만 다룬다). 그래서 **앱 부팅 시 1회 `caches.delete('api-cache')`** 를 함께 둔다.

삭제 지점을 로그아웃·로그인이 아니라 **부팅**으로 잡은 이유: 세션 확립 경로가 `LoginPage.jsx`(비밀번호 로그인)·`useAuthBootstrap.js`(OAuth) 둘로 흩어져 있어 훅을 걸면 지점이 여러 개가 되는데, 규칙을 제거한 뒤에는 **아무도 그 캐시를 재적재하지 않으므로** 부팅 1회 삭제가 전 경로를 단일 지점으로 덮는다. 계정 전환이 로그아웃을 거치지 않는 경우(토큰 만료 후 다른 계정 로그인)도 함께 덮인다.

**보정 (task#290 실행 중, 적대적 리뷰 MED 발견에서 파생) — 위 "단일 지점" 논거는 *새 SW가 활성화된 뒤에만* 성립한다.** 그 논거의 전제가 "아무도 재적재하지 않는다"인데, **옛 SW가 아직 살아 있는 전환 창에서는 옛 SW가 계속 재적재한다.** 그리고 `App.jsx::doLogout`은 **SPA 전용**이다(리로드·내비게이션 없음, 코드 직독으로 확인) — 그래서 "A 로그아웃 → 5분 내 같은 브라우저에서 B 로그인"이라는 **B47의 문서화된 주 도달 경로가 같은 문서 안에서 일어나 부팅을 재실행하지 않는다.** 즉 그 창에서는 주 경로가 열린 채였다.

그래서 `doLogout`에도 `purgeApiCache()` **한 줄을 추가**했다. 이는 기각한 대안 1(로그아웃 시에만 삭제)로의 회귀가 **아니다** — 대안 1은 *캐싱을 유지한 채* 삭제 지점만 두는 설계였고, 여기서는 규칙 제거가 정본이며 이 한 줄은 **전환 창 한정 보험**이다(새 SW 활성화 후에는 채우는 자가 없어 no-op). 대안 1의 기각 사유였던 "무표시 stale 시세가 남는다"는 규칙 제거가 이미 해소했다.

## 검토·기각한 대안 (Considered Options)

1. **로그아웃·로그인 시에만 캐시 삭제** — `CONCERNS.md` §14 항목 3이 원래 이 방향이었다. 기각: 로그아웃을 거치지 않는 계정 전환이 남고, **무표시 stale 시세는 그대로 남는다**(캐싱 자체를 유지하므로).
2. **사용자별 캐시 분리(`cacheKeyWillBeUsed`로 캐시 키에 신원 삽입)** — 기각: SW는 `localStorage`를 읽을 수 없어 신원을 IndexedDB나 `postMessage`로 넣어주는 **새 배선**이 필요하다. 그 배선이 새 실패 모드를 만들고, 신원 전달이 늦거나 실패하면 정확히 같은 도지가 재발한다. 이득(5분·50엔트리 폴백)보다 비용이 크다.

## 결과 (Consequences)

- **잃는 것**: 오프라인·느린 네트워크에서 `/api/*`의 5분·50엔트리 폴백. 실질 손실은 작다 — `globPatterns`가 `.html`을 제외하고 `navigateFallback: null`이며 프리캐시 목록에 `index.html`이 없어 **내비게이션은 이미 항상 네트워크를 탄다**(오프라인 셸이 애초에 성립하지 않는다). 5분 TTL·50엔트리는 오프라인 이야기가 아니라 "느린 회선에서 옛 값을 대신 보여주기"였다.
- **얻는 것**: 교차사용자 도지 제거 + 무표시 stale 금융 데이터 제거.
- ⚠️ **다시 넣지 말 것.** API 캐싱을 되살리려면 캐시 키에 신원이 들어가야 한다(대안 2). 그 배선 없이 규칙만 되돌리면 **B47이 그대로 되살아난다.** PWA에서 API 캐싱 부재는 다음 사람이 보면 이상하게 보이므로("왜 PWA인데 API를 캐시하지 않지?") 이 ADR이 그 되돌림을 막기 위해 존재한다.
- 규칙 제거는 **새 SW가 활성화된 뒤**에 효력이 있다. task#287의 SW 갱신 규율이 그 활성화를 담당한다. 활성화 전 창에서는 옛 SW가 계속 캐시하므로 **삭제 지점 2곳**(부팅 + `doLogout`)이 그 창의 방어선이다 — 부팅 삭제는 *방문 간* 이월을 끊고, `doLogout` 삭제는 *같은 문서 안* 계정 전환을 끊는다. (개정 전 이 줄은 "부팅 1회 삭제가 매 방문마다 노출 창을 좁힌다"였는데, 그 서술은 방문 간 이월만 다뤄 주 도달 경로를 못 덮었다 — 위 결정절 보정 참조.)
- ⚠️ **전환 창에 남는 잔여**: 로그아웃을 *거치지 않는* 계정 전환(토큰 만료 후 같은 문서에서 다른 계정 로그인)은 두 지점 어디에도 안 걸린다. 세션 확립 지점이 둘로 흩어져 있다는 위 이유가 그대로 적용되고, 새 SW가 활성화되면 자연 소멸하는 창이라 지점을 더 늘리지 않았다. 이 창을 없애려면 삭제가 아니라 **SW 활성화를 앞당기는 것**이 정답이다(아래).
- **후속 후보**: `vite.config.js`의 `injectRegister: 'auto'`가 만드는 `registerSW.js`는 등록을 **`window.load`에 게이팅**한다(`vite-plugin-pwa` 소스 직독). 즉 폰트 CDN fetch가 끝날 때까지 새 SW의 update-check조차 시작되지 않아 전환 창이 실제보다 길다. `injectRegister: 'inline'` 또는 `DOMContentLoaded`/즉시 `register()`로 당기는 것을 검토할 것 — 창의 실제 길이(수백ms인지 수초인지)는 라이브 계측이 필요하다(미측정, 추정으로 귀속하지 말 것).
- 삭제는 `api-cache` **한 키만** 지운다 — `google-fonts`·`cdn-fonts`·precache는 건드리지 않는다.
- 삭제 실패(`caches.delete` 거절)는 던지지 않되 `console.warn('[apiCachePurge] …')`로 **관측 가능**하다. 이 삭제가 전환 창의 유일한 방어선이라 무음 실패는 방어선 부재를 감춘다.
