# 0034 — 선도기술 리포트의 요약 레이어는 산문이 아니라 구조 필드로 싣는다 (그래프를 그리는 수치는 구조 데이터, 그리지 않는 요약 칩만 표시 문자열)

- 상태: 채택 (Accepted)
- 날짜: 2026-08-04
- 관련: task#281, [[ADR-0033]](0033-frontier-tech-report-non-ticker-resource.md)(비-티커 발행물·단위 규율), [[ADR-0027]](0027-analyst-report-separate-publication-resource.md)(발행물 모델·`points[]` 원형), [[ADR-0028]](0028-event-driven-routine-analysis-pipeline.md)(루틴이 콘텐츠 생산자), ADR-0006(기동 idempotent 마이그레이션), `CONTEXT.md`「선도기술 리포트」

## 맥락 (Context)

task#280이 상세 화면을 "지표·표 먼저, 산문은 하단"으로 재구성한 뒤에도, 이 문서에서 **가장 먼저 읽혀야 할 세 종류의 정보가 여전히 `description` 산문 안에만 있었다**:

1. **결론** — "이 기술의 요점이 무엇인가"가 4,700자 산문의 문장들에 흩어져 있다.
2. **연표** — "언제 무엇이 가동/착공/실증/계통연결됐나". SMR 실발행분에서 2020 로모노소프 가동 → 2023 HTR-PM → 2026 링룽 계통연결 → 2029 BWRX-300 → 2034 i-SMR이 **전부 문장 속에** 있었다. 이 기술의 핵심 정보가 정확히 그것인데도 화면 어디에도 축으로 존재하지 않는다.
3. **계보** — 업체가 어느 계열인가(SMR 노형: 경수형·비등수형·고온가스로·소듐냉각고속로). 표는 업체를 한 줄씩 나열할 뿐 계열로 묶지 못한다.

선택지는 둘이었다. **(A) 프론트가 산문을 파싱·요약한다** — 즉시 적용되고 재발행을 기다리지 않지만, 문장 추출 휴리스틱이 틀리면 화면이 발행물에 없는 사실을 말한다. **(B) 발행 스키마를 확장해 루틴이 채운다** — 정확하지만 다음 발행까지 빈 섹션이고, 컬럼 2개와 루틴 프롬프트 계약이 늘어난다.

여기서 [[ADR-0033]]과의 긴장이 생긴다. ADR-0033은 근거 항목에 **"표시용 문자열로 받기(심층 리포트 metrics 칩 방식) 기각 — 그래프를 못 그린다"**를 명시적으로 적어 뒀다. 그런데 이번에 추가하려는 `key_points[].metrics[].value`가 정확히 그 형태(`"1.1조원"`·`"22%"`)다. 경계를 적어두지 않으면 후임자가 **모순으로 읽고** 되돌리거나, 반대로 이 선례를 근거 삼아 시장 규모까지 문자열로 받는다.

## 결정 (Decision)

**1. 요약 레이어는 산문 파싱이 아니라 발행 스키마의 구조 필드로 싣는다.** (B)를 택한다 — `key_points[]`·`milestones[]`·`players[].category` 3필드를 추가하고, **프론트는 루틴이 쓴 것만 표시한다**. 산문에서 결론·연표를 추출하는 휴리스틱은 만들지 않는다(`wrong < missing`). 1/2가 도입한 `parseDescriptionSections`(대괄호 헤딩 → 접이식 소제목)는 *구조 분해*이지 *의미 추출*이 아니므로 이 금지선 안쪽이다.

**2. 세 필드는 전부 선택이고, 없으면 섹션째 생략한다.** 기술마다 채울 수 있는 것이 다르다 — 로봇·배터리엔 '노형' 같은 분류 축이 없고, 어떤 기술은 연표를 못 댄다. 빈 섹션(제목만 남은 유령)을 만들지 않으며, 게이트는 각 컴포넌트가 export한 채택 조건 순수함수를 페이지가 **그대로 호출**해 판정한다(`groupByCategory(...).length > 0` 등 — 느슨한 자체 판정을 쓰면 컴포넌트가 필터하는 입력에서 제목만 남는다).

**3. 경계: 그래프를 그리는 수치는 구조 데이터, 그리지 않는 요약 칩만 표시 문자열.**

- **구조 데이터로만 받는다(문자열 금지)** — `market.history/forecast[].size`(`{value, currency, unit}` enum), `market.cagr_pct`, `players[].share_pct`, `players[].tech_level`(1~5 이산), `players[].gap_years`(정수 년수), `difficulty.score`(1~5), **`milestones[].year`(정수)**. 이들은 곡선·축·밴드·타임라인 좌표를 만든다.
- **표시 문자열로 받는다** — `key_points[].metrics[].value` 하나뿐. 이 칩은 애초에 그릴 대상이 아니라 **읽을 대상**이고, 단위·통화·자릿수 표기를 루틴이 문맥에 맞게 고르는 편이 정확하다(`"2,700달러"`·`"134회"`·`"22%"`). 증감만 숫자(`change_pct`)로 받아 색을 결정론적으로 정한다.
- 따라서 **ADR-0033 결정 3이 기각한 것은 이 결정과 충돌하지 않는다** — 거기서 기각한 것은 *시장 규모를 문자열로 받아 성장 곡선을 못 그리게 되는 것*이었다. 판정 기준은 "문자열이냐"가 아니라 **"이 값으로 무엇을 그리는가"**다.

**4. `milestones[].status`는 추상 3단계 enum이다** — `done` | `in_progress` | `planned`. 구체 단계명("착공"·"계통연결"·"형식승인")은 기술마다 다르므로 자유 문자열 `event`가 담고, **색·마커는 이 3값이 결정론적으로 정한다**. 자유 문자열 상태를 허용하면 렌더러가 색을 고를 수 없거나 문자열 매칭 휴리스틱이 생긴다.

**5. 선택 필드는 `Optional[X] = Field(None)`으로 선언한다 — 예외 없음.** `x: float = Field(None)`은 키 생략만 통과시키고 **명시적 `null` 하나에 422**를 내 발행 요청 *전체*를 막는다(task#250 전체차단 실사례). 루틴이 "없음"을 `null`로 표현하는 것은 정상 입력이다. float 필드에는 `allow_inf_nan=False`를 함께 명시한다(task#211).

**6. 화면이 새 섹션을 보이려면 루틴이 채워야 하므로, 계약은 `scripts/cowork-routine-prompt.md`에 *지시*로 박는다.** 필드 의미·`status` 3값·`metrics` 상한 4개·"모르면 생략하되 산문에만 쓰는 것은 생략 사유가 아니다"를 프롬프트 본문에 쓴다. 설계 제약을 문서 한쪽에 배경지식으로만 남기면 무력하다.

## 근거 (Rationale)

- **(A) 프론트 산문 파싱** 기각: 문장 추출은 틀린 결론을 화면에 띄우고, 그 오류가 발행물에 근거가 없어 추적 불가다. 이 프로젝트가 반복해 택한 `wrong < missing`과 정면 충돌한다. 게다가 산문 형식은 루틴 프롬프트의 지시일 뿐 데이터 계약이 아니라(CONTEXT.md), 파서가 의존할 안정된 구조가 애초에 없다.
- **둘 다 채택**(파싱으로 즉시 + 스키마로 정확)도 기각: 같은 정보에 두 소스가 생겨 어느 쪽이 정본인지 화면이 답할 수 없다. 이 프로젝트가 이미 겪은 dual-source 가족(`tickers.name` ↔ `snapshots.data.name`)이다.
- **`key_points`를 `challenges`처럼 `{title, body}`로만 받기** 기각: 정량 근거가 다시 문장에 녹아 "한눈 구조화"(task#218)의 목적이 사라진다. 칩으로 분리해야 label/값이 스캔된다.
- **`metrics`에 구조 수치(`{value, unit, currency}`)를 요구** 기각: 이 칩이 담는 것은 금액만이 아니다(`"134회"`·`"1곳"`·`"48.9%"`). 단위 enum을 요구하면 표현 가능한 지표가 통화로 좁아지고, 실제로는 렌더러가 아무것도 계산하지 않으므로 얻는 것이 없다.
- **`status`를 자유 문자열로** 기각: 색·마커를 문자열 매칭으로 고르게 되어 `"완료"`/`"done"`/`"DONE"`이 각각 다른 렌더 결과를 낸다. 3값 enum이면 422가 발행 시점에 잡는다.
- **`category`를 enum·마스터 테이블로** 기각: 분류 체계가 기술마다 다르고(노형 ↔ 로봇 폼팩터 ↔ 전해질 계열) 4종이 고정도 아니다. 자유 문자열 + "없으면 전 업체 생략" 규율이 실질 비용 0이다.
- **계보를 DAG·트리 SVG로** 기각: 계보는 *묶음*이 본질이고 분류 간 방향 관계가 없다. 방향 없는 관계에 화살표를 그리면 그림이 데이터에 없는 사실을 말한다 — ADR-0033 결정 4가 `보완·경합`을 관계도에서 빼 칩 그룹으로 분리한 것과 같은 근거.
- **타임라인을 recharts로** 기각: ADR-0033 결정 4와 같은 근거(좌표가 순수함수면 vitest가 불변식을 직접 단언한다) + recharts 셀렉터 함정 3종(pie label이 별도 레이어 · 축 틱이 `.recharts-surface` 하위가 아님 · `.recharts-surface` 첫 매치가 범례 아이콘)을 원천 회피.
- **타임라인 SVG를 고정 `viewBox` + `width:100%`로** 기각: 컨테이너 폭에 비례해 **텍스트까지** 축소돼 350px에서 한글 라벨이 6~7px로 렌더된다(task#277 실측 — 기하는 전부 경계 안이라 넘침·잘림·겹침 축이 원리적으로 못 잡고 육안이 유일한 포착 수단이었다). 설계폭을 `minWidth`로 못박고 좁은 화면은 **자체 `overflow-x` 스크롤러**가 받는다(페이지 본문은 가로 스크롤하지 않는다).

## 결과 (Consequences)

- **컬럼 2개가 늘고 3표면을 쌍으로 유지해야 한다** — `app_schema.sql`(신규 설치) + `main._migrate`의 `ADD COLUMN IF NOT EXISTS`(라이브 DB, ADR-0006) + `save_report`의 INSERT 컬럼·VALUES·`ON CONFLICT DO UPDATE SET` **세 곳**. 한 곳만 고치면 배포 직후 발행이 깨지거나 upsert 경로에서 조용히 유실된다.
- **문서 5종이 계약에 묶인다** — `API_SPEC.md`·`CLAUDE_COWORK_API.md`·`scripts/cowork-routine-prompt.md`(박제본)·`README.md`(화면 구성)·`CONTEXT.md`. `test_api_doc_sync.py`는 엔드포인트 *존재*만 대조하므로 **이 필드들의 스키마 drift는 자동으로 잡히지 않는다** — 필드를 바꾸면 수동으로 5종을 함께 고쳐야 한다.
- **기존 발행물은 영구히 이 섹션이 없다.** 발행물은 불변이므로 구판의 `key_points`·`milestones`는 SQL NULL로 남고 `players[]`에는 `category` 키 자체가 없다. 소비자는 **배열 자리의 `null`과 `undefined`를 둘 다** 흡수해야 한다(`?? []`). 라이브 실데이터 2건(`smr`·`reusable-rocket`)이 정확히 그 상태이므로 구발행물 graceful은 이론이 아니라 현재 상태다.
- **새 섹션이 보이려면 루틴의 다음 발행을 기다려야 한다.** 30일 가드(ADR-0028) 때문에 자연 발행은 최대 한 달 뒤이며, 그전에 보려면 트리거 본문에 명시 범위 지정("smr을 재발행하라")으로 우선시켜야 한다 — 그것은 프로덕션 발행이므로 사람의 승인 사항이다.
- **경계가 문서로만 유지된다.** "그래프를 그리면 구조 데이터"는 코드가 강제하지 않는다 — 다음에 요약 칩이 아닌 값을 문자열로 받으려는 변경이 오면, 그것을 막는 것은 이 ADR을 읽는 사람뿐이다.
- **미커버로 남는 것**: 루틴이 세 필드를 *채울지*, 채운 내용이 정확한지는 어떤 코드도 검증하지 못한다. 스키마는 `status` enum·칩 상한·NaN 거부 같은 *형식*만 강제한다. 첫 실발행분은 사람이 한 번 읽어야 한다(ADR-0033과 같은 잔여 리스크).
